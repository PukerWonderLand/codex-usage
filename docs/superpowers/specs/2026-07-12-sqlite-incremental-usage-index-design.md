# SQLite 增量用量索引设计

## 背景

当前仪表盘与 `summary` 会扫描全部日志并把每条事件保存在 Node.js 堆内存中。后台网关默认堆上限为 256MB；当日志达到约 17 万条后，首次加载或自动刷新可能触发 V8 `FatalProcessOutOfMemory`，进程异常退出且无法自动恢复。

## 目标

- 仪表盘与 `summary` 的常驻内存不再随事件总数线性增长。
- 未变化的日志文件不重复解析。
- 变化文件逐行写入磁盘索引，不在内存构造事件数组。
- 保持现有 API 响应结构、筛选语义、趋势比较和页面行为。
- `json`、静态导出和 `detail=full` 继续读取原始日志，保持完整明细能力。

## 兼容范围

使用 Node 内置 `node:sqlite`，不增加第三方原生依赖。根据 Node 官方文档，该模块从 22.5 提供，22.13 起无需 `--experimental-sqlite`，因此最低 Node 版本调整为 `>=22.13`。

## 架构

新增 `src/usage-store.js`，负责以下边界：

1. 发现 Codex home、项目日志和 JSONL 文件。
2. 用文件大小与修改时间判断文件是否变化。
3. 未变化文件直接跳过；变化文件在单文件事务中删除旧记录并逐行重新写入。
4. 删除已不存在或已取消导入文件对应的记录。
5. 使用 SQLite 聚合查询生成 metadata、totals、timeline、channels、homes、models、projects 和 comparison。

`src/usage-core.js` 保留原始报告与内存索引能力，同时新增流式事件扫描入口。原有内存索引构建复用同一入口，避免两套解析规则漂移。

`src/server.js` 仅缓存 SQLite 同步状态和指纹，不再缓存全量事件。并发请求共享同一个同步 Promise，避免重复重建索引。

`src/cli.js summary` 使用同一磁盘索引；`json` 继续走完整报告。

## 数据库结构

### `source_files`

记录文件路径、所属来源、文件大小、修改时间和最近索引时间。文件路径为主键。

### `events`

每行保存一个紧凑事件：时间戳、会话、home、渠道、项目、模型以及五类 token。额外保存本地小时、日期、周和月份键，避免查询时依赖 SQLite 的时区实现。

事件通过 `source_path` 关联来源文件并启用级联删除。时间、home、渠道、项目和模型建立查询索引。

### `store_meta`

保存 schema 版本、最近生成时间和最近指纹。schema 不兼容时明确报错，避免静默返回错误统计。

## 数据流

### 首次加载

发现所有来源文件，逐文件流式解析并写入 SQLite。内存中只保留当前 JSONL 行、少量会话解析状态和聚合查询结果。

### 自动刷新

先计算文件指纹。指纹未变化时直接查询现有数据库；变化时只重建大小或修改时间发生变化的文件，然后执行聚合查询。

### 导入目录变化

导入配置变化后使同步状态失效。下一次请求发现新增或删除文件，并对应写入或清理数据库记录。

## 查询语义

日期边界继续由 `usage-core` 的本地时间规则计算。SQLite 只负责在边界内执行 `COUNT`、`COUNT(DISTINCT session_id)` 与 token 求和。时间线按预存 bucket key 分组，小时补零和上一周期趋势继续复用核心模块逻辑。

## 错误处理

- 单文件解析或写入失败时回滚该文件事务，并把错误加入 warnings。
- 旧记录在事务回滚后仍然保留，避免局部失败清空已有统计。
- 数据库目录自动创建。
- HTTP 仍通过现有 500 JSON 格式返回无法恢复的数据库错误。

## 测试

- SQLite 汇总与现有内存汇总结果一致。
- 文件未变化时不重复索引。
- 会话文件追加后累计 token 差值正确且不重复。
- 项目日志新增、删除与取消导入正确同步。
- server 与 CLI summary 使用 SQLite，完整明细仍保持原行为。
- 256MB 网关连续强制刷新真实数据时保持存活。

## 已知取舍

当前版本采用文件级增量：变化文件会逐行重建自身记录。它保证内存与总事件量解耦，但单个超大且持续追加的项目日志仍会让刷新耗时随该文件增长。后续可在不改变数据库查询层的前提下增加字节偏移和解析状态，实现单文件追加式索引。
